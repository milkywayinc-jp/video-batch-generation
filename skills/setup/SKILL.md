# 動画一括生成のセットアップ

利用者が導入を明示的に開始したときだけ実行する。単にZIPをダウンロード・clone・閲覧した段階ではGoogle Driveやチャットへ書き込まない。

このファイルから2階層上がパッケージルート。配布版は`templates/releases/2026-10-20-v1.json`。元の作業シートの最新版へ自動追従しない。保存済み基準版をコピーし、その後は各利用者が自分のコピーを自由に変えられる。

1. Google Drive接続/gws CLIと作業場所を確認する。既存の認証を使い、認証情報をファイルやチャットへ貼らせない。未実装の接続を接続済みと説明しない。依存関係は[README](../../README.md)。
2. 管理者から受け取った基準版URL、私有の`local/template-source.json`、またはGoogle Driveの完全一致のタイトル候補から、基準版を一意に確認する。候補の所有者・保存場所を照合し、曖昧な同名ファイルを勝手に選ばない。アクセスできなければ管理者への確認が必要と返す。共有範囲を広げたり、公開GitHubへ原本URLや台本を追記したりしない。
3. 利用者の作業場所の`.video-batch/`などに私有state-dirを置く。`python3 scripts/video_batch.py setup --source-id ID --release RELEASE --state-dir PRIVATE_STATE`で基準版の内容・書式ハッシュを照合する。異なる版なら停止する。変更された元シートで古い版を黙って置き換えない。
4. 明示セットアップの許可範囲で同コマンドへ`--apply`を付ける。本人のMy Drive/ChatGPTに台本込みのネイティブコピーを作る。再実行は同じstateを使い、作成済みコピーを再利用する。別端末や状態消失時の候補は利用者へ示し、選択後に`--reuse-copy-id ID`、別コピーを求めた場合だけ`--create-another`を使う。通信結果不明なら照合し、再送しない。チャット作成が失敗してもシートを再作成しない。
5. コピーURLを渡す。原本と別ID、台本・数式・結合・書式の保持を確認する。リンク先の素材・フォルダ・他チャットはコピーされない。素材/保存先/引継ぎ先を読み、利用者が使える場所を確認する。未確定はpendingとして一覧化し、元の共有保存先へ書き込まない。変更する場合は本人のコピーだけを対象にする。
6. 公式onboardingが新しい会話を開いたなら、その会話を制作チャットとする。既存会話でセットアップしており、利用者が新しい制作チャット作成まで指示した場合は、公式create_threadが使えれば作成する。プロジェクト指定ならlist_projectsで実在するものを選ぶ。初期メッセージには生成した`production-chat-prompt.txt`と制作スキルのパッケージ場所を渡す。現在の会話履歴を丸ごとコピーしない。
7. 新規チャット作成機能がない場合は、コピーURLと開始文を渡して利用者が新しいチャットを開く。自動作成できたとは言わない。`setup-finish --state-dir PRIVATE_STATE --destinations JSON --chat-id VERIFIED_ID`、または`--manual-handoff`で実際の状態を記録する。新規作成したチャットにはツールが要求するcreated-thread表示を出す。
8. コピーURL、配布版、制作チャット/手動開始文、未確定の素材/接続を短く渡す。動画生成・課金API・広告配信・他チャットへの送信はセットアップ完了の副作用として実行しない。

制作は[制作スキル](../video-batch-generation/SKILL.md)に従う。コピー内のルール変更と配布基準版の版更新は分ける。新しい基準版は管理者の明示指示で作り、既存版を上書きしない。
